# تخطيط الرحلات بدون موديل لغوي — 26 أكتوبر 2026

هذا هو مسار التخطيط المعتمد حاليًا. لا يستخدم Qwen أو Ollama أو أي واجهة لموديل لغوي، ولا يعتمد على دفتر Colab. الشات بوت مؤجّل ومستقل عن هذا المسار.

## كيف يعمل؟

1. الباك إند يتحقق من بيانات الرحلة والصلاحيات.
2. أدوات مستقلة تجلب الأماكن وعروض الطيران والفنادق حسب المزوّد المفعّل. المزوّدان الأخيران لم يُحددا بعد، لذلك بياناتهما الحالية تجريبية.
3. ترتيب الأماكن يعتمد على الاهتمامات، وجودة البيانات، والقرب والتنوع، مع استبعاد المكرر والمغلق وغير الصالح.
4. خوارزمية محلية تختار الأنشطة وتوزعها على الأيام؛ تراعي التوفر بالأوقات، وفترات الوصول والمغادرة، وميزانية جميع المسافرين، وتجنب زيارة المكان نفسه مجددًا.
5. Google Routes يفحص مدد التنقل عند تفعيله. إذا لم تلائم بعض الأنشطة الأوقات تُختصر نهاية اليوم غير الممكنة، ويُذكر ذلك بوضوح. لا يتم افتراض مسار غير متحقق عند تخطي محطة وسطية.
6. الـAgent يقيّم التغطية والتكلفة والتكرار والأيام الفارغة؛ يمكنه إجراء بحث أماكن إضافي واحد موجّه للاهتمامات الناقصة، وتجربة ثلاث مسودات كحد أقصى باستراتيجيات تغطية أو تقارب مختلفة.
7. أفضل خطة صالحة تُحفظ مع تقرير فحوصاتها في MySQL. اختيارات المستخدم للطيران والفندق تبقى محفوظة ما لم يطلب تغييرها.

## حدود واضحة

- هذه خوارزمية ترتيب وجدولة بقواعد وأوزان واضحة، وليست نموذج ML مدرّبًا أو حلًا يضمن أفضل خطة رياضيًا.
- مدد الزيارة الافتراضية: 90 دقيقة للمتاحف والمعارض وحدائق الحيوان والأحواض المائية، و60 دقيقة لباقي الأنشطة؛ كلها تقديرات معلنة.
- أوقات التنقل وساعات العمل تعكس البيانات المتاحة ولا تضمن التوفر أو الزحام في موعد السفر.
- رسوم الأنشطة المجهولة تبقى مجهولة. لا يُفترض أنها مجانية، ولا يُخلط السعر بعملة أخرى.
- أسباب الاقتراح تُكتب بقوالب عربية/إنجليزية من حقول المكان والحسابات؛ لا تُولّد حقائق تاريخية.
- التعديلات تستخدم خيارات الاهتمام والإيقاع والميزانية والعروض؛ التعليمات النصية الحرة غير مدعومة وتُرفض بدل تجاهلها بصمت.

## الإعداد والتشغيل

`AI_PROVIDER=rules` هو إعداد الخوارزمية الحالية؛ الاسم قديم لأغراض التوافق، ولا يشير إلى استخدام موديل لغوي. `mock` مخصص لبيانات الاختبارات. القيمتان `ollama` و`external` لم تعودا مدعومتين للتخطيط.

شغّل `START-GILGAMISH.cmd`. ملف التشغيل لم يعد يشغّل Ollama أو يفحص وجود موديل. `npm run providers:check` يعرض حالة الخدمات بدون المفاتيح.

فحوصات متاحة:

```text
npm test
npm run build
npm run agent:check
node scripts/check-live-journey.mjs --routes
```

الفحص الأخير يستخدم قاعدة `gilgamish_test_agent` المنفصلة وأماكن ومسارات Google الفعلية، وينظف حساب الاختبار بعد الانتهاء. لا ينفّذ أي حجز. دليل التجربة محفوظ في `docs/verification/rules-live-journey.json`؛ نتائج النموذج اللغوي القديمة تاريخية فقط.

## نتيجة التحقق

نجح 59 اختبارًا للباك إند، وبناء الواجهة، واختبار MySQL باستخدام الخوارزمية الفعلية. تجربة Google الكاملة أنتجت 6 أنشطة ليومين خلال 1.699 ثانية في هذه العينة، وحفظت الخطة وتقريرها. مراقبة اتصالات HTTP سمحت فقط بـGoogle Places وGoogle Routes؛ لم يحدث أي اتصال بموديل لغوي. الرسوم المجهولة بقيت مجهولة. الموقع أُعيد تشغيله وفحصه على http://localhost:5180 مع plannerEngine=rules.

بعد تثبيت قائمة الديمو التي اختارها المستخدم، صار العدد 64 اختباراً ناجحاً مع بناء الواجهة. نجح أيضاً فحص بحث Google Places الأساسي للمدن العشر. تفاصيل القائمة وحدود مكة/جدة موثقة في `docs/DEMO-CITIES.md`؛ فحص MySQL والرحلة الكاملة المذكور أعلاه يظل تجربة مستقلة سابقة.
