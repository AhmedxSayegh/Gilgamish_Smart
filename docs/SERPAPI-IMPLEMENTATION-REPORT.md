# تقرير تكامل SerpApi Google Hotels

التاريخ: 29 أكتوبر 2026 — Asia/Damascus.

تم تنفيذ التكامل داخل `D:\Codex-Sarh-Technology\Gilgamish-Smart` بعد فحص الخادم والواجهة ومزوّدي السفر ومسارات البحث والتخطيط والحفظ وتكامل IGNAV. لم يُنشر المشروع، ولم تُنفّذ حجوزات أو مدفوعات. لم يُعد تشغيل أي خادم سابق؛ يجب إعادة تشغيل الخادم المحلي المفتوح مسبقاً لتحميل الإعدادات الجديدة.

## نتائج الفحص والتنفيذ

- الخادم Express، والواجهة React/Vite، والتخزين MySQL. خدمات السفر قابلة للاختيار بصورة مستقلة؛ كان مزوّد الفنادق المحلي `mock`، والطيران `ignav`، والأماكن والمسارات `google`.
- أُضيف محوّل SerpApi إلى عقد الفنادق الموجود، فتستفيد منه نتائج البحث والترشيحات وتوليد الخطط دون تغيير تنفيذ IGNAV.
- المفتاح يُقرأ حصراً من محتويات `backend/.env` عبر dotenv، دون قبول بديل من بيئة النظام أو ملفات الواجهة أو جسم الطلب. المفتاح الموجود لم يُنسخ أو يُغيّر؛ تغيير الملف المحلي اقتصر على `HOTELS_PROVIDER=serpapi`.
- أُضيفت واجهات البحث والتفاصيل وأسعار البائعين وروابط الحجز الخارجية. كل مسار يتطلب جلسة مستخدم وسياق رحلة أو نسخة خطة يملكها، مع رفض الحقول الزائدة والرموز والتواريخ غير الصالحة.
- زر «احجز الآن» في نتائج الفنادق والخطط المحفوظة يجلب التفاصيل والأسعار ويعرض روابط البائعين الآمنة. لا يحدث انتقال خارجي أو اتصال بالمزوّد لجلب التفاصيل قبل ضغط المستخدم. نسخ الخطط تستخدم تواريخها الأصلية حتى بعد تعديل الرحلة.
- الأسعار الكلية للإقامة منفصلة عن أسعار الليلة. الضرائب تُعرض باعتبارها مشمولة أو مستثناة أو غير مؤكدة. الفنادق التي لا تملك إجمالي إقامة مرصوداً لا تدخل حسابات الترشيح والميزانية.
- بيانات الفنادق والرموز الطويلة تُحفظ في لقطة JSON الموجودة. تُستخدم بصمة للرموز التي تتجاوز طول عمود المعرّف الحالي، دون ترحيل قاعدة البيانات.

## المسارات

تحت `/api`، ومع `?tripId=UUID` أو `?planId=UUID` حصراً:

| الطريقة والمسار | الوظيفة |
| --- | --- |
| `GET /hotels/search` | البحث عن الفنادق ذات إجمالي إقامة مرصود |
| `GET /hotels/:propertyToken` | التفاصيل وأسعار البائعين |
| `GET /hotels/:propertyToken/prices` | الأسعار مع حالة الضرائب ووقت الرصد |
| `GET /hotels/:propertyToken/booking-links` | روابط البائعين وموقع الفندق عند توفره |

تستخدم الواجهة `propertyToken` المُعاد من البحث. ما زالت الروابط الخارجية تتطلب مراجعة التواريخ والغرفة والنزلاء والسعر النهائي لدى البائع.

## الحماية وحدود الاستهلاك

- طلبات المزوّد تذهب إلى عنوان SerpApi ثابت فقط. لا تُستخدم روابط الاستجابة لتنفيذ اتصالات خادم إضافية.
- الاستجابات تحتوي حقولاً محددة؛ لا تُعاد بيانات المزوّد الخام أو أخطاؤه أو روابط SerpApi التي قد تتضمن المفتاح.
- تُرفض روابط الحجز غير المشفّرة، أو المحتوية على بيانات دخول أو مفاتيح، أو المتجهة إلى عناوين محلية/API، والتحويلات المتداخلة غير الآمنة.
- حد مسارات الفنادق والترشيحات: 30 طلباً لكل مستخدم خلال 15 دقيقة.
- الحدود الافتراضية للمزوّد: 20 محاولة في الدقيقة، و100 محاولة في اليوم بتوقيت UTC، واتصالان متزامنان. تشمل جميع مداخل المزوّد، بما فيها توليد الخطط.
- تخزين مؤقت لخمس دقائق، ودمج الطلبات المتطابقة، ومشاركة طلب التفاصيل بين التفاصيل والأسعار والروابط، ومهلة اتصال 20 ثانية. لا توجد إعادة محاولات تلقائية تستهلك رصيداً إضافياً.
- تُحتسب محاولات الاتصال الفاشلة؛ لا تُحتسب إصابات التخزين المؤقت. يؤدي رد المزوّد 429 إلى انتظار 60 ثانية. الأخطاء الموجّهة للمستخدم مترجمة إلى العربية، مع أكواد واضحة وتوقيت إعادة المحاولة عند تحديد الاستهلاك.

عدادات الاستهلاك محلية لكل عملية وفي الذاكرة: تعاد عند تشغيل الخادم من جديد، ولا تتشاركها عمليات خادم متعددة. حدود حساب SerpApi مستقلة عنها.

## حدود التحقق

التسعير الحالي لغرفة واحدة وبالغين فقط. يرفض النظام تسعير الأطفال لأن نموذج الرحلة لا يجمع الأعمار؛ لم تُخترع أعمار أو أسعار. الاختبار الحقيقي خاص بإسطنبول وإقامة 28 نوفمبر إلى 2 ديسمبر 2026، لشخصين وبعملة SAR؛ لا يثبت توفر المخزون لكل المدن والتواريخ، ولا صلاحية إتمام كل رابط لدى البائع. لم تُنفّذ رحلة حقيقية كاملة تجمع اتصال IGNAV وGoogle وSerpApi؛ اختُبرت مسارات التطبيق والحفظ باستجابات متحكماً بها، وSerpApi الحقيقي بصورة مستقلة.
